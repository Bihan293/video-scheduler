# Заявка в TikTok Content Posting API — пошагово

## 0. Что должно быть готово

- [ ] Публичный HTTPS-домен приложения (Render/VPS), не GitHub Pages.
- [ ] Рабочий OAuth callback: `https://ДОМЕН/auth/tiktok/callback`.
- [ ] Страницы `/privacy.html` и `/terms.html` с реальным email.
- [ ] Демо-видео 1–2 минуты: авторизация + загрузка + результат.
- [ ] Тестовый TikTok-аккаунт, добавленный в Sandbox приложения.
- [ ] Файл подтверждения домена TikTok в корне домена (если запрошен).

## 1. Создание приложения

1. Войдите на <https://developers.tiktok.com/> под аккаунтом TikTok.
2. **My Apps → Connect an app** (или Create app).
3. Название: `Video Scheduler` (или ваше), категория — инструмент для авторов.
4. Иконка 1024×1024, короткое описание, сайт.
5. В **Products** добавьте:
   - **Login Kit**;
   - **Content Posting API**.
6. В настройках Login Kit:
   - Redirect URI: `https://ДОМЕН/auth/tiktok/callback`;
   - Scopes: `user.info.basic`, `video.upload`, `video.publish`.
7. Скопируйте **Client Key** и **Client Secret** в env приложения.

> Redirect URI должен совпадать символ в символ. `http` вместо `https`,
> лишний слэш или `www` — частая причина `redirect_uri mismatch`.

## 2. Подтверждение домена

TikTok может попросить положить файл вида
`tiktokwGTZ1z4TGFKydRugLlWeQNeAOjAXOYyd.txt` в корень домена.

- На GitHub Pages он уже лежит в репозитории.
- Для приложения на Render положите файл в `site/` — FastAPI отдаёт
  `/{tiktok...}.txt` из этой папки. Проверьте:
  `https://ДОМЕН/tiktokw....txt` → должен вернуть текст файла.

## 3. Sandbox и тестовые пользователи

1. В приложении откройте **Sandbox**.
2. Добавьте TikTok-аккаунт, на котором будете тестировать.
3. Пока приложение не одобрено, API работает только для добавленных
   тестовых пользователей.
4. Пройдите полный сценарий: вход → загрузка → черновик/публикация.

## 4. Что снимать в демо

TikTok проверяет, что приложение реально использует API, а не показывает
статичный макет.

Обязательные кадры:

1. Начало авторизации: виден домен приложения и кнопка подключения.
2. **Настоящий экран TikTok** с названием вашего приложения и списком scopes.
3. Возврат в приложение: виден подключённый username.
4. Выбор видеофайла и ввод описания.
5. Процесс загрузки (прогресс/статус).
6. Результат: видео в черновиках TikTok или опубликовано.
7. По возможности — откройте TikTok и покажите сам черновик/пост.

Требования:

- без склеек, скрывающих шаги;
- без чужих видео и водяных знаков;
- интерфейс на языке, который поймёт ревьюер (русский допустим, но подписи
  лучше продублировать по-английски);
- длина 1–2 минуты, разрешение 720p+;
- звук не обязателен, но голосовое пояснение помогает.

Наш автосценарий: `scripts/record_demo.py`. В демо-режиме он показывает
локальный экран авторизации с пометкой «Демо». Для заявки запустите его на
деплое с реальными ключами — тогда откроется настоящий `tiktok.com`.

## 5. Аудит Content Posting API

Пока аудита нет:

- `video.upload` (черновики) — обычно доступен тестовым пользователям;
- `video.publish` (прямая публикация) — ограничен; TikTok может разрешать
  только приватные посты (`SELF_ONLY`) или возвращать ошибку.

После аудита:

- доступна прямая публикация с выбранным `privacy_level`;
- снимаются ограничения на список пользователей (в рамках правил).

В заявке опишите честно: «инструмент для авторов, загружает собственные видео
пользователя; публикация только после явного выбора режима; токены хранятся на
сервере; есть отключение аккаунта и удаление данных».

## 6. Чек-лист перед отправкой

- [ ] `https://ДОМЕН/` открывается без ошибок.
- [ ] `/privacy.html` и `/terms.html` открываются, email рабочий.
- [ ] Redirect URI в TikTok = `TIKTOK_REDIRECT_URI` в env.
- [ ] OAuth проходит на телефоне и на десктопе.
- [ ] Видео до 20 МБ проходит через сайт; через бота — до 20 МБ.
- [ ] Статус в кабинете меняется: загрузка → обработка → черновик/публикация.
- [ ] Кнопка «Отключить» удаляет аккаунт.
- [ ] Демо-видео показывает настоящий TikTok OAuth (не демо-экран).
- [ ] В описании приложения нет слов «официальное приложение TikTok».
- [ ] Указано, что приложение не аффилировано с TikTok.

## 7. Частые причины отказа

| Причина | Как исправить |
|---|---|
| Демо показывает макет, а не реальный OAuth | Перезапишите на деплое с реальными ключами |
| Redirect URI не совпадает | Скопируйте строку из env в кабинет TikTok |
| Нет privacy policy/terms | Опубликуйте `site/` и укажите ссылки |
| Приложение просит лишние scopes | Оставьте только `user.info.basic`, `video.upload`, `video.publish` |
| Не видно, как пользователь выбирает видео | Покажите файл, описание и нажатие «Загрузить» |
| Нет подтверждения домена | Положите `tiktok*.txt` в корень и проверьте URL |
| Прямая публикация не работает | Это нормально до аудита; используйте черновики |

## 8. После одобрения

1. Переключите `DEMO_MODE=0`.
2. Проверьте прямую публикацию на тестовом аккаунте.
3. Настройте очистку видеофайлов и бэкап SQLite.
4. Добавьте шифрование токенов и CSRF-защиту, если сервис публичный.
